# ADR-0005: 애그리게이트 간 검증을 소유 서비스에 위임한다 (ProductService가 CategoryRepository를 직접 의존하지 않는다)

## 상태
채택

## 배경 (이걸 왜 고민했고, 어떤 상황이었는가)
단순히 서비스가 작동하게만 구현하지 않고 그 역할을 더 잘할 수 있는 객체에게 책임을 위임하는 것으로 객체지향적으로 코드를 작성할 수 있다.

상품을 추가할 때 지켜야 할 규칙으로, categoryId가 존재하는지, 최하위 카테고리에 추가되는지가 있었다.
```java
//기존 코드
@Service
@RequiredArgsConstructor
public class ProductService {

    private final ProductRepository productRepository;
    private final CategoryRepository categoryRepository;

    @Transactional
    public void create(Long categoryId, String name, String description) {
        if (!isLeaf(categoryId)) throw new IllegalStateException("상품은 최하위 카테고리에만 추가할 수 있습니다.");
        productRepository.save(new Product(categoryId, name, description));
    }
    
    public boolean isLeaf(Long categoryId) {
        if (!categoryRepository.existsById(categoryId)) throw new IllegalStateException("존재하지 않는 카테고리입니다.");
        return categoryRepository.countDescendants(categoryId) == 0;
    }
}
```
규칙을 지키기 위해 처음에는 위와 같이 코드를 작성했다.
큰 틀에서는 catalog라는 도메인안에 묶여있지만, catalog안에서도 구분이 되는 개념들이다.
Category는 계층 구조를 가진다는 데이터 구조의 규칙만 가질 뿐 Category 자체에는 규칙이 없어 도메인으로 판단하지 않았고, 
Product는 판매 상태, 생성 규칙 등의 영향을 받기 때문에 도메인으로 선언하였다.

Category에 대한 검증은 이미 존재하는 CategoryService가 더 잘 할수 있기 때문에 위처럼 CategoryRepository에서 직접 데이터를 가져와서 검증하는 코드를
ProductService에 작성할 필요가 없다고 판단하였다.

## 결정
```java
//변경 코드
@Service
@RequiredArgsConstructor
public class ProductService {

    private final ProductRepository productRepository;
    private final CategoryService categoryService;

    @Transactional
    public void create(Long categoryId, String name, String description) {
        categoryService.validateLeafForProduct(categoryId);
        productRepository.save(new Product(categoryId, name, description));
    }
}


@Service
@RequiredArgsConstructor
public class CategoryService {

    private final CategoryRepository categoryRepository;

    public void validateLeafForProduct(Long categoryId) {
        if (!categoryRepository.existsById(categoryId)) throw new IllegalStateException("존재하지 않는 카테고리입니다.");
        if (categoryRepository.countDescendants(categoryId) > 0) throw new IllegalStateException("상품은 최하위 카테고리에만 추가할 수 있습니다.");
    }
}
```

## 결과
- ProductService는 CategoryRepository에 직접 접근하여 데이터를 가져오고 검증을 진행하지 않는다.
  - 이 검증을 더 잘할 수 있는 CategoryService에 역할을 위임하는 것으로 책임이 줄어든다.
